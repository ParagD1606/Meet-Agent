## memory/  (agent MEM)
- `scope.ts`: `type SlackScope={channelId:string;isPrivate:boolean;isIm:boolean;userId:string|null}`; `writeTag(s):string|null` (public→"shared", private channel→`channel_${id}`, DM→`user_${userId}`, DM w/o user→null); `readTags(s):Promise<string[]>` (always "shared"+own tag; DM also adds `channel_X` for every private channel in `channel_members` the user belongs to).
- `embed.ts`: `embed(texts:string[]):Promise<number[][]>` (batching, OpenAI-compatible embeddings API via EMBEDDING_*/MODEL_BASE_URL; throws clear error if unconfigured).
- `search.ts`: `searchMemory({tags:string[];query:string;limit?:number /*40*/}):Promise<MemoryHit[]>`; `MemoryHit={id:number;text:string;scopeTag:string;source:string;sourceRef:string|null;score:number;createdAt:Date}`. tags REQUIRED & non-empty (throw otherwise). Hybrid pgvector cosine + tsvector, reciprocal-rank fusion, threshold 0.3, active only.
- `supersede.ts`: `addFact({tag,text,source,sourceRef?}):Promise<{id:number;superseded:number[]}>` — dedupe near-duplicates, LLM contradiction check against nearest same-tag facts, mark old `status='superseded', superseded_by`, create `memory_edges` to similar facts.
- `writeback.ts`: `captureTurn({scope:SlackScope;transcript:string}):Promise<number>` LLM extracts durable facts (decisions, owners, deadlines) → `addFact` into `writeTag(scope)`; no-op when tag null.
- `ingest.ts`: `ingestDocument({tag:string;name:string;mimeType:string;data:Buffer|string;source:string;sourceRef?:string}):Promise<number>` — text/markdown/pdf(unpdf)/csv/html extraction, chunk (~800 tokens, overlap), embed, insert `kind='chunk'`; replaces prior chunks with same (source,sourceRef).
- `graph.ts`: `getGraph({tags,limit}):Promise<{nodes:{id:number;label:string;scope:string;kind:string}[];edges:{source:number;target:number;weight:number}[]}>`; `listMemories({tags,q?,limit,offset})`; `deleteMemory(id)`.

# Token efficiency & management (cross-cutting, REQUIRED in every area)
Goal: best-in-class cost/latency. Targets measured by `scripts/bench-tokens.ts` (B owns; replays a scripted 30-message thread + recall + tool use against the real local model and prints the per-component breakdown, before vs after): **input tokens per turn ≥50% lower than the pass-1 baseline on the long thread; prefix byte-identical across users within a workspace (cache-stable); recall ≤2.5k tokens; tool-schema tokens ≤1.5k for a turn with ≤10 relevant tools; trivial turns (greetings/thanks) use ≤1 cheap-model call and no recall/tools.**
1. **Measure first.** Every turn records `turns.inputTokens/outputTokens/cacheReadTokens/cacheWriteTokens/costMicros/model/steps/depth/promptBreakdown` (first-step approx tokens of system, coreBlocks, skills, toolSchemas, history, recall, toolResults, user via B's `estimateTokens`). C's `turn/loop.ts` aggregates AI-SDK `usage` over all steps and writes these; B supplies `estimateTokens`, `breakdown()` and `estimateCostMicros`; A supplies `recordUsage` (usage_daily) and `GET /api/usage?range=7d|30d` → `{byDay:[{day,turns,inputTokens,outputTokens,costMicros}],byUser,byModel,byRole,cacheHitRate,avgBreakdown,topTurns}` (admin).
2. **Depth router (C):** cheap model (role `triage`) or heuristics classify each turn `direct | memory | tools | deep`; `direct` = no recall, no tools, one `main`-or-`triage`-model call; `memory` = recall only; `tools` = recall + only relevant tool families; `deep` = full toolset + higher step cap. Greetings/acks never trigger recall or extraction. Heuristics first (length, `?`, URLs, mentions, verbs), model only when ambiguous.
3. **Tool schema diet (C+D):** toolset chosen per trigger (chime/automation/research: minimal read-only; DM vs channel; never include write tools when `readOnly`); short descriptions (≤25 words each, no examples); MCP tools beyond a threshold are not listed — exposed via `search_tools`/`call_tool` (D); tool-family enabling (`enable_tool_family`) for rare families (web, slack-search, automations, research).
4. **History diet (B `buildContext`):** rolling structured summary + recent window sized by TOKENS (default 3k) not message count; strip Slack markup noise, quoted/duplicate bot text, long pasted blobs (spill with handle); per-message cap; never re-send resolved tool traffic.
